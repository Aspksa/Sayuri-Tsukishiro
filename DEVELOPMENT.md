Требования инструмента: Python 3.10+; Git для сравнения и повышения. Сторонние Python-пакеты не нужны. Проверено в доступном Linux-окружении; запуск непосредственно на Windows пользователя не проверялся.

Из корня проекта:

```sh
python scripts/versioning.py show
python scripts/versioning.py bump
python scripts/versioning.py check
python -m unittest discover -s scripts/tests -v
```

`show` работает без Git в скачанном ZIP. `bump` и `check` требуют Git-копию. Тесты создают отдельные временные репозитории и не меняют рабочие файлы проекта. Это команды инструмента разработки, а не запуск помощницы.

## Осмотр локальной копии

Команды выполняются из корня уже полученной локальной копии репозитория. Они предназначены для осмотра, а не запуска приложения:

```sh
git status --short --branch
git remote -v
git log -5 --oneline
git diff --stat
git diff
git diff --cached
git ls-files
```

Перед копированием вывода в отчёт убери возможные секреты из URL и изменений. Отсутствие локальной копии не мешает прочитать ветку, историю и файлы через GitHub; такой способ не проверяет локальный запуск.

## Запись проверки

Для каждой существенной проверки сохраняй в `PROJECT_STATE.md`:

`ревизия/рабочая копия → окружение → команда или способ → результат → ограничения`.

Для документации проверь содержание, относительные ссылки и чтение сохранённых файлов. Не помечай тесты приложения пройденными, если проверялись только Markdown-файлы.

## Ошибки и неудачные попытки

Активные проблемы хранятся в `PROJECT_STATE.md`. Формат:

`симптом → как воспроизвести → что уже пробовали → результат → вывод/следующая гипотеза`.

Если результат не установлен, пиши «не проверено». Перед повтором попытки укажи новую причину. При разрыве связи сначала проверь, завершилась ли операция фактически.

Когда появится подтверждённое постоянное решение типовой ошибки, добавь его сюда: симптом, причина, исправление и проверка. Сейчас проверенных рецептов устранения ошибок приложения нет.

### Структура

| Путь | Назначение |
| --- | --- |
| `app/` | ядро, конфигурация, SQLite, HTTP server, preflight |

### Запуск на Windows

Из корня проекта двойным щелчком:

`Sayuri Tsukishiro.bat`

Первый запуск при отсутствии `.runtime/python` загружает Python 3.14.8 с python.org, проверяет SHA256, выполняет preflight, запускает локальный сервер и после health-check открывает браузер. Корень вычисляется относительно BAT, поэтому буква USB/SSD не фиксируется.

### Команды разработки

```sh
python -m unittest discover -s app/tests -v
python -m unittest discover -s scripts/tests -v
python -m app.preflight
python -m app.main --no-browser
python scripts/versioning.py show
python scripts/versioning.py check
```

На Linux допустим `python3`. Для пользовательского Windows-запуска системный Python не требуется после успешной установки локального runtime.

### Runtime paths

- База: `data/sayuri.db`.
- Launcher log: `logs/launcher.log`.
- Core/server log: `logs/sayuri.log`.
- Начальный URL: `http://127.0.0.1:8765`; если порт занят, перебирается ограниченный диапазон.
- API: `GET /api/health`, `GET /api/events?limit=N`.

Windows BAT/PowerShell не запускались в текущем Linux-окружении; этот предел проверки должен оставаться отмеченным до фактического запуска на Windows.
