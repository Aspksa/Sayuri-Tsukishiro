## Осмотр локальной копии

Команды выполняются из корня уже полученной локальной копии репозитория. Они предназначены для осмотра, а не запуска приложения:

```sh
git status --short --branch
git remote -v
git log -5 --oneline
git diff --stat
git diff
git diff --cached
git ls-files
```

Перед копированием вывода в отчёт убери возможные секреты из URL и изменений. Отсутствие локальной копии не мешает прочитать ветку, историю и файлы через GitHub; такой способ не проверяет локальный запуск.

## Запись проверки

Для каждой существенной проверки сохраняй в `PROJECT_STATE.md`:

`ревизия/рабочая копия → окружение → команда или способ → результат → ограничения`.

Для документации проверь содержание, относительные ссылки и чтение сохранённых файлов. Не помечай тесты приложения пройденными, если проверялись только Markdown-файлы.

## Ошибки и неудачные попытки

Активные проблемы хранятся в `PROJECT_STATE.md`. Формат:

`симптом → как воспроизвести → что уже пробовали → результат → вывод/следующая гипотеза`.

Если результат не установлен, пиши «не проверено». Перед повтором попытки укажи новую причину. При разрыве связи сначала проверь, завершилась ли операция фактически.

Когда появится подтверждённое постоянное решение типовой ошибки, добавь его сюда: симптом, причина, исправление и проверка. Сейчас проверенных рецептов устранения ошибок приложения нет.
