## ДНК 0.4 — Evidence Engine

### Нормализация и доказательность

Каждая молекула теперь получает:

- стабильный `fact_id`;
- тип и роль в документе;
- исходное значение;
- нормализованное машинное значение;
- общую уверенность;
- отдельную уверенность извлечения, нормализации и источника;
- статус `fact`;
- quality gate: `accepted / review / rejected`;
- источник со строкой, фрагментом и `evidence_hash`.

Нормализуются:

- даты → ISO;
- суммы → числовое значение + RUB;
- проценты/пробег/количество → число + единица;
- ИНН, КПП, ОГРН, БИК и банковские счета;
- VIN;
- госномер;
- телефон;
- e-mail;
- время;
- номер документа;
- ФИО;
- организация.

### Профили типов документов

Добавлены профили:

- Служебная записка;
- Путевой лист;
- Договор;
- Счёт-оферта;
- Счёт;
- Приказ;
- Распоряжение;
- Выписка ГСМ;
- Акт;
- Накладная;
- общий Документ.

Для профиля считаются обязательные/ожидаемые факты и процент полноты.

### Действия и время

Локально распознаются доказуемые действия по строкам:

- просьба;
- приказ/назначение;
- согласование;
- информирование;
- оплата;
- поставка/передача.

Временная модель отличает:

- дату документа;
- крайний срок;
- дату периода;
- время выезда;
- время возвращения;
- обычное упоминание даты/времени.

### Арифметика

Для XLSX-таблиц, где определены колонки количества, цены и суммы, проверяется:

`Количество × Цена = Сумма`.

Несовпадение становится критическим риском и блокирует передачу непроверенных фактов в память.

### Противоречия

Внутри документа проверяются ключевые singleton-поля профиля.

Между документами ДНК динамически сравнивает документы одного типа с одинаковым номером и проверяет расхождения по:

- итоговой сумме;
- дате документа;
- ИНН;
- VIN;
- госномеру.

Междокументный слой пересчитывается при чтении ДНК, поэтому исправленный конфликт не остаётся навсегда.

### Семантический отпечаток и дубли

Для содержимого строятся:

- semantic SHA-256;
- 64-bit SimHash;
- компактный набор token hashes.

По ним определяются:

- точные дубли;
- почти-дубли;
- связанные документы.

SHA-256 исходного файла остаётся отдельным доказательством физической идентичности.

### Entity resolution и граф

Сущности получают канонический ключ:

- транспорт;
- организация;
- человек;
- контакт;
- финансы;
- время;
- документ.

Формируется graph-ready слой:

`document → mentions → entity`

и

`document → contains_action → action`.

В граф не добавляются выдуманные причинные связи.

### Quality Gate

Факт не считается готовым знанием только потому, что был найден.

Quality Gate учитывает:

- наличие доказательства;
- нормализацию;
- уверенность;
- целостность файла;
- критические риски;
- внутренние противоречия;
- междокументные противоречия.

Поле `memory_ready` разрешает будущей памяти использовать только проверяемый слой.

### Версии ДНК

Схема Диска повышена до 4.

Новые таблицы:

- `disk_dna_history`;
- `disk_dna_feedback`.

Каждое реальное переизучение получает номер версии и `version_delta`.

Дельта показывает:

- добавленные факты;
- удалённые факты;
- изменившиеся типы фактов;
- изменение классификации;
- изменение полноты профиля.

Переименование/перемещение файла не заставляет заново разбирать содержимое, если SHA-256 и версия анализатора не изменились.

### Обратная связь и обучение

Внутренний API поддерживает:

- подтвердить факт;
- отклонить факт;
- исправить значение.

Исправления хранятся отдельно и повторно применяются поверх ДНК. Они не изменяют оригинальный документ.

### Качество документа

Внутренне считается оценка:

- целостность;
- наличие текстового слоя;
- полнота профиля;
- доля принятых фактов;
- необходимость OCR;
- усечение предпросмотра.

### Эпистемика

ДНК явно разделяет:

- доказанные факты;
- гипотезы.

В текущем локальном движке гипотезы не создаются. Непроверенный вывод не превращается в знание автоматически.

## API без нового UI

- `GET /api/disk/files/{id}/dna`
- `POST /api/disk/files/{id}/dna/analyze`
- `GET /api/disk/files/{id}/dna/history`
- `POST /api/disk/files/{id}/dna/feedback`

## Ограничения

- OCR для сканов/PDF-изображений ещё не подключён.
- Реальный ИИ-провайдер ещё не подключён.
- Семантические причинные связи, сложные роли и выводы не имитируются.
- «Фоновая очередь» тяжёлого анализа пока не выделена в отдельный worker; текущий pipeline выполняется локально синхронно.

## Следующий этап

После подтверждения ДНК 0.4 — подключение OCR и реального ИИ-провайдера поверх уже доказательного слоя, без переделки структуры ДНК.
