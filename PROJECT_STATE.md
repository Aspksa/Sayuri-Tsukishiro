## Реализовано

- В левом меню добавлен отдельный пункт **«Диск Sayuri»**.
- Отдельный модуль `disk/` зарегистрирован как `sayuri-disk`.
- Файлы хранятся локально в `data/disk/objects/` под UUID, а не под пользовательскими именами.
- Метаданные хранятся в общей SQLite-базе в таблицах модуля Диска.
- Для каждого файла сохраняются имя, MIME-тип, размер, SHA-256, папка и дата загрузки.
- Реализованы папки и хлебные крошки.
- Реализованы загрузка файлов кнопкой и перетаскиванием.
- Реализованы поиск в текущей папке, скачивание и удаление.
- Папка удаляется только пустой.
- Максимальный размер одного файла в первой версии: 1 ГБ.
- Загрузка идёт потоково по 1 МБ и не держит весь файл в оперативной памяти.
- Перед записью метаданных файл сохраняется во временный объект; после завершения выполняется атомарный перенос.
- Имена проверяются; пути пользователя не используются как реальные пути хранения.
- Для скачивания возвращается сохранённая SHA-256.
- События загрузки/создания/удаления пишутся как события «Диск Sayuri».

## API Диска Sayuri

- `GET /api/disk` — содержимое корня/папки и статистика.
- `POST /api/disk/folders` — создать папку.
- `POST /api/disk/upload` — потоковая загрузка файла.
- `GET /api/disk/files/{id}/download` — скачать файл.
- `DELETE /api/disk/files/{id}` — удалить файл.
- `DELETE /api/disk/folders/{id}` — удалить пустую папку.

## Проверки

После публикации CI должен проверить:
- сервис Диска Sayuri;
- полный HTTP-сценарий папка → загрузка → список → скачивание → удаление;
- SHA-256 и сохранность байтов;
- Unicode-регистр имён папок;
- защиту от опасных имён;
- контракт веб-интерфейса;
- существующие тесты ядра, настроек, версий, preflight и Windows launcher.

## Что ещё не реализовано

Это фундамент Диска Sayuri, а не финальная замена облачным дискам. Пока нет корзины, истории версий файла, предпросмотра документов, прав доступа, синхронизации между устройствами, ИИ-паспорта документа, OCR/индексации и семантического поиска.
