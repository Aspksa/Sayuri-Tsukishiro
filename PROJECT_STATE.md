## Sayuri Safe Actions 0.1

Добавлен локальный Action Broker: `agent/actions.py`.

Цепочка выполнения:

```text
команда в чат
→ локальный детерминированный планировщик
→ pending action
→ карточка действия в чате
→ явное подтверждение Господина
→ однократное выполнение разрешённого инструмента
→ аудит результата
```

Ни одно изменение проекта через этот контур не выполняется автоматически.

## Разрешённые инструменты

### disk.create_folder

Создаёт новую папку в текущей папке Диска Sayuri либо в корне.

Пример:

`создай папку Договоры 2026`

### disk.set_favorite

Меняет флаг избранного текущего открытого объекта.

Примеры:

`добавь этот документ в избранное`

`убери этот документ из избранного`

### disk.trash_current

Перемещает текущий открытый файл/объект в корзину.

Пример:

`удали этот документ`

Перед выполнением всегда требуется подтверждение.

### disk.move_current

Перемещает текущий открытый объект в существующую папку.

Пример:

`перемести этот документ в папку Договоры`

Папка назначения разрешается только при однозначном точном имени или полном пути. При неоднозначности действие завершается ошибкой без изменения данных.

### memory.remember

Добавляет подтверждённое решение в проектную память.

Пример:

`запомни как решение проекта: все изменения требуют новой версии`

## Безопасность Action Broker

Каждое действие получает:

- случайный action ID;
- фиксированный tool ID из allowlist;
- неизменяемый payload;
- SHA-256 payload;
- уровень риска;
- статус;
- время создания;
- срок подтверждения 10 минут;
- результат или ошибку.

Статусы:

- `pending`;
- `executing`;
- `completed`;
- `cancelled`;
- `expired`;
- `failed`.

Подтверждение replay-safe: повторный confirm уже выполненного action не запускает инструмент повторно.

Конкурирующие подтверждения защищены атомарным переходом `pending -> executing` через SQLite `BEGIN IMMEDIATE`.

## Сохранённые границы

- Cloud.ru остаётся единственным AI-провайдером.
- Единственная модель: `deepseek-ai/DeepSeek-V4-Flash`.
- Личная и проектная память остаются разделены.
- Содержимое документа не отправляется в Cloud.ru автоматически.
- LLM не выполняет инструменты напрямую.
- Планирование поддерживаемых изменяющих команд на этом этапе локальное и детерминированное.
- Неизвестная команда идёт в обычный чат, а не в инструмент.

## Проверки

Добавлены тесты:

- действие не исполняется на этапе plan;
- обязательное подтверждение;
- отмена pending action;
- replay-safe повторное подтверждение;
- создание папки выполняется только после confirm;
- решение проекта сохраняется только после confirm;
- HTTP plan/confirm/replay flow;
- UI-контракт карточек подтверждения;
- JavaScript syntax и Windows launcher.

Перед публикацией изменения собираются одним атомарным коммитом от `0.1.38` и проходят полный workflow Versions.
