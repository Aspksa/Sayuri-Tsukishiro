## Semantic Memory

Добавлен локальный модуль `agent/semantic_memory.py`.

Это намеренно **не neural embeddings** и не вторая LLM. Поиск полностью локальный и не требует сети.

Текущий engine: `hybrid-semantic-v1`.

Он объединяет:

- совпадение ключевых слов;
- лёгкую нормализацию словоформ;
- локальный словарь смысловых понятий;
- character n-grams для похожих формулировок;
- importance/confidence записи.

Это позволяет находить близкие формулировки, например «белый интерфейс» по запросу о «светлой теме», не нарушая разделение `personal/project`.

### Границы

- личная память не выдаётся как проектная и наоборот;
- поиск не вызывает Cloud.ru;
- retrieval не меняет содержимое памяти;
- при использовании записи увеличивается только счётчик use-count;
- текущая реализация рассчитана на локальную память до нескольких сотен/первых тысяч записей, без тяжёлой vector DB.

В Личном кабинете поиск по памяти теперь использует гибридную релевантность, а найденная запись показывает процент смыслового совпадения.

## Experience Learning

Добавлен локальный модуль `agent/experience.py`.

Хранилище:

`data/sayuri-experience.db`

Опыт отделён от обычной памяти и не смешивается с фактами/предпочтениями.

Записываются подтверждённые исходы:

- успешные и неуспешные Safe Actions;
- отменённые/истёкшие действия как нейтральные исходы;
- принятые и отклонённые кандидаты Memory Intelligence;
- явная пользовательская оценка ответа Sayuri: «Полезно» / «Не помогло».

Полный диалог в Experience Learning не копируется. Для оценённого ответа хранится ограниченный task-context: prompt, короткий excerpt ответа и безопасный UI-context.

## Как опыт используется

### Калибровка Memory Intelligence

Для стратегии вида:

`memory.personal.preference`

Sayuri считает сглаженную успешность по подтверждённым решениям пользователя.

Если накоплено минимум 3 значимых исхода, experience может немного корректировать confidence нового кандидата памяти.

Коррекция ограничена диапазоном ±8%, поэтому опыт не может полностью переопределить детерминированные правила Memory Guardian.

### Контекст для чата

Перед запросом к DeepSeek-V4-Flash Sayuri ищет релевантный прошлый опыт локально тем же hybrid semantic механизмом.

В модель отдельно передаются:

- `helpful` — релевантный положительный опыт;
- `avoid` — релевантный отрицательный опыт.

Этот блок явно помечается как справочные данные, а не инструкции и не доказательство факта.

## Обратная связь в чате

У ответов DeepSeek-V4-Flash появились кнопки:

- «Полезно»;
- «Не помогло».

Каждый AI-ответ получает локальный `response_id`.

Оценка:

- idempotent;
- повторная оценка того же response заменяет предыдущий outcome, а не создаёт дубликат;
- хранится только локально;
- обновляет Experience Learning и статистику стратегий.

## API

Новые/расширенные API:

- `GET /api/sayuri/experience`;
- `POST /api/sayuri/experience/feedback`;
- `GET /api/sayuri/memory?q=...` — при поисковом запросе использует Semantic Memory.

API обратной связи принимает:

- `response_id`;
- `rating=useful|not_useful`;
- `prompt`;
- `answer`;
- безопасный UI-context.

## Сохранённые архитектурные ограничения

- единственный внешний AI-провайдер — Cloud.ru;
- единственная LLM — `deepseek-ai/DeepSeek-V4-Flash`;
- Semantic Memory не добавляет вторую модель;
- личная и проектная память остаются раздельными;
- Experience Learning не даёт новых разрешений инструментам;
- изменяющие действия остаются confirmation-gated;
- документы и память передаются модели только как недоверенные данные;
- API-ключ не попадает в GitHub.
