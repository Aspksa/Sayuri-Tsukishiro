## ДНК 0.5 — Structural Intelligence & Safety

Базовый Evidence Engine 0.4 сохранён. Новый слой расположен в `disk/dna_advanced.py` и работает поверх доказательной ДНК.

### Пространственные доказательства

Каждый факт получает `source.locator`.

Для текстовых документов:
- строка;
- тип блока.

Для таблиц:
- таблица;
- строка;
- найденные колонки;
- ячейка, если значение однозначно найдено.

Для PDF/изображений без OCR координаты честно помечаются `pending_ocr`, а не выдумываются.

### Document Schema Engine

Из фактов строится машинная схема документа:
- идентичность;
- стороны;
- транспорт;
- финансы;
- время;
- действия;
- обязательные и отсутствующие поля.

### Entity Resolution 2.0

Сущности группируются в кластеры. Приоритет идентификаторов:
- организация: ИНН → каноническое имя;
- транспорт: VIN → госномер;
- остальные сущности: канонический ключ.

Объединение выполняется только по детерминированным доказательствам; вероятностное объединение без ИИ не используется.

### Obligation Engine

Из доказуемых действий строятся обязательства:
- тип действия;
- текст;
- возможный исполнитель;
- срок;
- документ-основание;
- источник;
- уверенность.

Поддерживаются просьба, приказ/назначение, согласование, оплата и поставка/передача.

### Temporal Contradiction Engine

Локально проверяются:
- срок раньше даты документа;
- возвращение раньше выезда;
- информационное замечание о требовании оплаты без найденного основания рядом.

Только противоречия уровня attention/critical блокируют quality gate.

### Dependency Graph

Номера других документов превращаются в зависимости. ДНК пытается разрешить ссылку в уже изученный файл и создаёт доказуемое ребро:

`document → depends_on → document`.

### Template Fingerprint

Структурный отпечаток документа строится по:
- типу;
- режиму содержимого;
- нормализованным заголовкам;
- ролям фактов;
- числу колонок.

Конкретные номера, даты и числа удаляются из шаблонного отпечатка, поэтому разные заполнения одной формы могут распознаваться как один шаблон.

### Document Family

Документы одного типа с одинаковым номером объединяются во внутреннее семейство:
- оригинал/редакции/копии;
- участники семейства;
- общий family ID.

### Corpus Anomaly Engine

Когда накоплено минимум несколько документов одного типа, ДНК сравнивает текущий документ с медианой корпуса:
- размер файла;
- количество слов;
- полнота профиля.

Сильные отклонения помечаются как аномалии, но не объявляются ошибкой без доказательства.

### Семантический version diff

История ДНК теперь дополнительно показывает:
- значения до/после по типу и роли;
- числовую и процентную дельту суммы;
- изменение шаблона;
- изменение количества обязательств;
- изменение числа рисков.

### Calibration & Correction Memory

Обратная связь пользователя используется в двух режимах.

**Калибровка:** после минимум 5 подтверждений/исправлений/отклонений одного типа факта рассчитывается надёжность типа.

**Correction Memory:** автоматическое правило коррекции разрешается только когда одна и та же каноническая ошибка одинаково исправлена минимум в трёх разных документах.

Одно исправление никогда не превращается в глобальное правило.

### Tamper-evident Evidence Ledger

Схема Диска повышена до 5.

Новая таблица `disk_dna_ledger` хранит hash-chain:
- номер события;
- тип;
- payload SHA-256;
- hash предыдущего события;
- chain hash.

Журнал не заявляется криптографически неизменяемым хранилищем, но обнаруживает изменение или разрыв цепочки.

### Prompt Injection Shield

Внутри документа обнаруживаются фразы, похожие на:
- игнорирование предыдущих инструкций;
- подмену system prompt;
- смену роли;
- команды shell/PowerShell;
- запрос секретов.

Любой такой текст остаётся в trust domain `document_content` и никогда не становится системной или инструментальной командой Саюри.

### Sensitive Data Classification

ДНК классифицирует:
- ФИО;
- телефон;
- e-mail;
- банковские реквизиты;
- бизнес-идентификаторы.

Для будущего внешнего ИИ персональные и финансовые значения помечаются к редактированию.

### Selective AI Context

Будущей модели не потребуется передавать весь файл. ДНК заранее собирает минимальный контекст:
- только допустимые факты;
- confidence;
- evidence hash;
- обязательства;
- trust-domain;
- отредактированные чувствительные значения.

### Knowledge Promotion Pipeline

Внутренние стадии:

`extracted → normalized → matched → checked → confirmed → knowledge`.

Найденный или даже проверенный факт не становится долговременным знанием автоматически. Для стадии knowledge требуется подтверждённая политика памяти.

### ДНК пакета документов

Добавлен внутренний агрегатор папки:
- сколько файлов;
- сколько уже изучено;
- типы документов;
- общие сущности;
- обязательства;
- противоречия;
- сколько документов прошли memory gate.

API:
- `GET /api/disk/package-dna?folder_id=...`
- `GET /api/disk/files/{id}/dna/ledger`

## DISK-006 — DNA Evolution Core 0.6

Пользовательский интерфейс не расширялся. Путь остаётся:

**Просмотр → ДНК → Свойства**

### Evolution Core

Добавлен отдельный модуль `disk/dna_evolution.py` версии `0.6.0`.

Он работает поверх Evidence Engine 0.5 и не заменяет доказательную основу.

Внутренние контуры:

- Self Review — проверка собственной согласованности ДНК;
- Regression Guard — защита от ухудшения нового анализа относительно уже проверенных фактов;
- Adaptive Profile — безопасные ожидания по типу документа на основе корпуса;
- Rule Lifecycle — candidate / shadow / active для корректирующих правил;
- Hypothesis Lab — повторяющиеся связи остаются гипотезами, а не фактами;
- Active Learning — очередь наиболее важных и неопределённых фактов на будущую проверку;
- Experience Snapshot — техническая метрика накопленного проверяемого опыта.

### Глобальный реестр сущностей

Схема Диска повышена до 6.

Новые таблицы:

- `disk_dna_entities`;
- `disk_dna_entity_mentions`.

Организация, автомобиль и другие канонические сущности теперь могут иметь один глобальный ID во многих документах.

Реестр обновляется лениво при чтении/анализе ДНК и не требует массового тяжёлого переанализа при запуске приложения.

### Безопасная эволюция

ДНК 0.6 не имеет права автоматически превращать повторяемость в знание.

Гарантии:

- гипотеза ≠ факт;
- association ≠ causality;
- адаптивное поле ≠ обязательное поле;
- новое правило не становится active при конкурирующем исправлении;
- потеря уже проверенных фактов блокируется Regression Guard;
- провал Self Review блокирует `memory_ready`.

### Защита от деградации анализатора

Regression Guard сравнивает новую ДНК с предыдущей версией:

- потерянные accepted/confirmed факты;
- падение полноты профиля;
- изменение типа документа;
- уверенность классификации.

При серьёзной регрессии новая ДНК сохраняется для аудита, но не считается безопасной для будущей памяти.

### Адаптивные профили

После накопления минимум 5 документов одного типа движок может определить типы фактов и роли, встречающиеся минимум в 70% корпуса.

Они записываются как `learned_expected`, но не становятся обязательными автоматически.

### Гипотезы

Если две сущности встречаются вместе минимум в трёх документах, может появиться association hypothesis.

Она всегда имеет:

- `status=hypothesis`;
- `causal=false`;
- `promotion_allowed=false`.

### Защита повторного переизучения

Из реального пользовательского лога выявлен сценарий нескольких последовательных `POST /dna/analyze`.

Теперь обычный повтор с неизменным SHA-256 и тем же анализатором в течение 10 секунд:

- не создаёт новую версию ДНК;
- не создаёт новую ledger-запись;
- возвращает `reanalysis_deduplicated=true`.

Внутренний `deep=true` обходит cooldown и действительно создаёт новый глубокий анализ.

### Внутренние API

- `GET /api/disk/dna/evolution` — состояние Evolution Core;
- `GET /api/disk/dna/reanalysis-plan?limit=N` — рекомендуемый план переанализа;
- существующий `POST /api/disk/files/{id}/dna/analyze` принимает `{"deep": true}` для явного обхода cooldown.

План переанализа только рекомендует работу и ничего массово не запускает автоматически.

## DISK-007 — Spatial Intelligence & OCR 0.7

Пользовательский интерфейс не расширяется. Пользовательский путь остаётся:

**Просмотр → ДНК → Свойства**

### Пространственный движок

Добавлен `disk/dna_spatial.py` версии `0.7.0`.

Архитектура:
- PDFium / `pypdfium2 5.13.0` — PDF, страницы, native text и геометрия;
- Pillow 12.3.0 — растровые страницы;
- Tesseract OCR 5.5.3 — локальный OCR;
- `rus+eng` — закреплённые language data;
- Evidence Engine 0.7 получает распознанный текст и остаётся единственным источником молекул фактов.

### Spatial evidence

Для найденного факта может сохраняться:
- страница;
- global line;
- line ID;
- bbox в координатах страницы;
- нормализованный bbox 0..1;
- extraction method: native / OCR;
- статус координаты `exact_from_document_engine`.

Координаты не синтезируются. Если геометрия недоступна, факт остаётся без spatial locator.

### OCR policy

OCR запускается, когда:
- на странице нет native text;
- native text слишком мало;
- явно запрошен OCR.

Защита производительности:
- максимум 120 страниц spatial-разбора;
- максимум 24 OCR-страницы за один анализ;
- OCR DPI 220;
- таймаут Tesseract 75 секунд на страницу.

Если OCR runtime отсутствует или страница не обработана:
- анализ не объявляется успешным OCR;
- причина сохраняется в `ocr.failures`;
- основной проект продолжает работать.

### Quality

Для OCR сохраняется реальная confidence Tesseract по словам и средняя confidence страницы.
Отдельно рассчитывается document/spatial quality.

Quality не выдаётся за вероятность истинности факта — это качество извлечённого слоя.

### Таблицы, подписи и печати

Без внешней semantic/vision модели ДНК работает консервативно:
- выравненные текстовые колонки → `table_candidate`;
- ключевые слова подписи/М.П. → зона-кандидат;
- подходящий page object → `stamp_shape_candidate`.

Кандидаты не превращаются автоматически в подтверждённые таблицы, подписи или печати.

### Хранилище

Схема Диска: `7`.

Новая таблица:
- `disk_dna_spatial` — кэш spatial/OCR snapshot по SHA-256 и версии движка.

Полная spatial-модель хранится отдельно от компактной ДНК, чтобы не раздувать основной JSON документа.

### API без нового меню

- `GET /api/disk/dna/spatial` — диагностический статус spatial runtime;
- `GET /api/disk/files/{id}/dna/spatial` — полный spatial snapshot;
- `GET .../dna/spatial?ocr=1` — явный OCR snapshot;
- `POST .../dna/analyze` принимает `{"ocr": true}`;
- `{"deep": true}` остаётся режимом полного повторного анализа.

### Windows runtime

Bootstrap остаётся переносимым и без pip:
- wheel PDFium/Pillow закреплены версиями и SHA-256;
- Tesseract installer 5.5.3 закреплён SHA-256;
- rus/eng traineddata закреплены SHA-256;
- optional spatial runtime не должен блокировать запуск Саюри при сетевой/установочной ошибке;
- на ARM64 автоматическая установка Tesseract отключена, но внешний Tesseract может быть обнаружен.

### Preflight

Preflight теперь отдельно выводит `диск_sayuri`, чтобы schema_version системной БД не путалась со схемой Диска.
