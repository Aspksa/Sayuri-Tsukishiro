## D-004 — Версия проекта и каждого модуля при любом изменении

- Дата: 2026-10-05.
- Статус: принято.
- Источник: прямое указание пользователя о версии модуля, новой версии при любом изменении и хранении номеров в локальных папках проекта.
- Решение: общая версия в корневом `VERSION`; каждый модуль имеет `VERSION` в своей папке. Любой коммит с изменением повышает проект и затронутые модули.
- Реализация: [VERSIONING.md](VERSIONING.md), [MODULES.json](MODULES.json), [scripts/versioning.py](scripts/versioning.py).
- Начальная фиксация: проект `0.1.1`, служебный модуль `dev-tools 0.1.0`. Это способ внедрения требования; пользователь отдельно не задавал эти числовые значения.
- Причина: GitHub, скачанная папка и следующий чат должны однозначно определять ревизию компонентов.
- Следствие: документация тоже повышает общую версию; новый модуль регистрируется только вместе с реальной папкой.
- GitHub Release не создаётся автоматически; прикладной стек и модель этим решением не выбираются.

## D-005 — Local-first ядро на standard library + SQLite

- Дата: 2026-10-05.
- Статус: принято.
- Источник: прямой запрос пользователя начать профессиональное ядро, БД и веб-сайт.
- Решение: первая рабочая основа использует Python standard library, `sqlite3` и локальный HTTP-сервер без сторонних Python-пакетов.
- Причина: минимальная поверхность зависимостей, переносимость, простой bootstrap и предсказуемая диагностика.
- Безопасность: сервер в `0.1.x` привязан только к `127.0.0.1`; внешний доступ не включается без отдельной модели аутентификации и авторизации.

## D-006 — Переносимый Windows runtime

- Дата: 2026-10-05.
- Статус: принято.
- Источник: пользователь потребовал запуск `Sayuri Tsukishiro.bat` с любого носителя.
- Решение: launcher использует относительный корень проекта и локальную `.runtime/`. При отсутствии runtime bootstrap скачивает официальный embeddable Python 3.14.8 для AMD64/ARM64, проверяет SHA256 и запускает preflight.
- Следствие: буква диска не зашивается; первый запуск требует интернет только если runtime ещё не сохранён.


## D-007 — CORE-002: системные настройки и граница Agent Core

- Дата: 2026-10-05.
- Статус: принято.
- Источник: пользователь поручил сделать левое меню, перенести техническую информацию в «Настройки» и профессионально реализовать CORE-002.
- Решение: системные настройки без секретов хранятся в SQLite и проходят серверную проверку типов и диапазонов. Agent Core выделяется отдельным модулем-контрактом, независимым от конкретного AI-провайдера.
- Интерфейс: постоянное левое меню содержит «Главная» и «Настройки»; в «Настройки» входят конфигурация, состояние, события и архитектура.
- Безопасность: сервер остаётся привязан только к 127.0.0.1.
- Ограничение: контракт Agent Core не означает подключённую модель, память или инструменты; выполнение агента пока выключено.


## D-008 — Модуль «Диск Sayuri»

- Дата: 2026-10-05.
- Статус: принято.
- Источник: пользователь потребовал добавить в левое меню модуль с точным названием **«Диск Sayuri»** и развивать его как более мощное файловое пространство.
- Решение: «Диск Sayuri» является отдельным модулем `sayuri-disk` с собственной версией. Пользовательское название во всех видимых местах — строго «Диск Sayuri».
- Хранение: бинарное содержимое находится в `data/disk/objects/` под UUID; исходные имена не используются как файловые пути. Метаданные находятся в SQLite.
- Целостность: при загрузке вычисляется SHA-256; загрузка идёт потоково через временный файл и завершается атомарным переносом.
- Безопасность: имена проверяются на обход путей и управляющие символы; сервер остаётся локальным на `127.0.0.1`.
- Первая версия: папки, поиск в папке, загрузка, drag-and-drop, скачивание, удаление и статистика.
- Ограничение: корзина, версии файлов, синхронизация, паспорт документа, OCR, ИИ-анализ и семантический поиск относятся к следующим этапам и не считаются реализованными в 0.1.6.


## D-009 — Диск Sayuri 0.2 как профессиональный файловый менеджер

- Дата: 2026-10-05.
- Статус: принято.
- Источник: пользователь поручил развить Диск Sayuri до профессионального файлового менеджера и сделать рабочий макет.
- Решение: версия модуля Диск Sayuri повышается до 0.2.0. В файловый слой входят корзина и восстановление, избранное, недавние, история действий, переименование, перемещение, массовые операции, сортировки, фильтры, размеры папок, свойства и прогресс загрузки.
- Целостность: удаление папки в корзину распространяется на всё поддерево; восстановление возвращает поддерево целиком; окончательное удаление удаляет физические объекты.
- Совместимость: схема Диска 1 автоматически мигрирует в схему 2 без удаления данных.
- Конфликты: имена проверяются на уровне операций; миграция не вводит жёсткое ограничение, способное сломать старую базу с ранее допустимыми дублями.
- Дубликаты: SHA-256 используется для обнаружения совпадающего содержимого, но одинаковое содержимое не удаляется автоматически.
- Интерфейс: рабочий макет является частью веб-приложения, а не отдельной картинкой.
- Следствие: версии файлов, цифровой паспорт, предпросмотр, OCR и ИИ-анализ остаются отдельным следующим этапом DISK-003.


## D-010 — Центральный просмотр и контекстное управление Диск Sayuri

- Дата: 2026-10-05.
- Статус: принято.
- Источник: пользователь потребовал убрать историю снизу, перенести загрузку наверх, добавить правую кнопку мыши, улучшить длинные имена, иерархию папок, просмотр Office и свойства.
- Решение: файл открывается в центральном модальном окне. В нём объединены вкладки «Просмотр» и «Свойства». Правая кнопка мыши и кнопка «•••» дают одинаковое контекстное меню.
- Длинные имена: в основной таблице и центральном окне имя не обрезается до одной строки; используется перенос с полным title.
- Папки: в левой части Диска отображается отдельное дерево папок с текущей папкой.
- Форматы: браузерно поддерживаемые файлы открываются inline; DOCX/XLSX/PPTX и ODF-пакеты разбираются локально стандартной библиотекой для безопасного предпросмотра.
- Ограничение: предпросмотр Office не означает полноценное редактирование бинарного Office-документа. Редактирование содержимого будет отдельным этапом, чтобы не повреждать оригиналы.
- Приватность: предпросмотр выполняется локально и не отправляет содержимое внешним сервисам.


## D-011 — Диск Sayuri без второго сайдбара и с drag-and-drop

- Дата: 2026-10-05.
- Статус: принято.
- Источник: пользователь потребовал убрать внутренний блок «Мой диск / Избранное / Недавние / Корзина», расширить рабочую область, добавить плитки/список и настоящее перемещение мышью.
- Решение: разделы Диска находятся в верхней компактной панели. Второго постоянного сайдбара внутри Диска нет.
- Ширина: Диск использует расширенный холст с максимумом 1380 px; на меньших экранах занимает доступную ширину.
- Представление: пользователь переключает «Плитки» и «Список»; выбор сохраняется локально в браузере.
- Drag-and-drop: одиночные и массово выделенные файлы/папки можно переносить на папку; папка подсвечивается и может автоматически открыться после ~900 мс наведения.
- Корзина: верхняя кнопка «Корзина» является drop-target.
- Отмена: сервер возвращает исходное положение объектов; пользователь может отменить перенос через уведомление.
- Папки: карточка показывает рекурсивное количество файлов и общий размер.
- Окно перемещения: увеличено примерно до 720 px и показывает дерево назначения отдельно от выбранного пути.


## D-012 — «ДНК» как глубокий профиль документа

- Дата: 2026-10-05.
- Статус: принято.
- Источник: пользователь выбрал точное название «ДНК» и потребовал изучать документ «с ног до головы», от структуры до молекул, при минимальном визуальном шуме.
- Решение: в центральном окне файла порядок вкладок фиксируется как **Просмотр → ДНК → Свойства**.
- Модель данных: ДНК хранится отдельно от оригинала в `disk_dna` и привязана к `file_id`, SHA-256, состоянию источника и версии анализатора.
- Текущий локальный слой: идентичность, целостность, структура, тип документа, молекулы с источниками, кандидаты сущностей, проверки качества и стадийность.
- Доказуемость: каждая извлечённая молекула хранит строку и фрагмент источника.
- Честная граница: без реального ИИ-провайдера Саюри не выдумывает семантические отношения, причины и противоречия; раздел «Связи» показывает ожидание семантического слоя.
- UX: ключевые показатели видны сразу, подробности скрыты в раскрываемых блоках; по умолчанию открыта только «Анатомия документа».
- Безопасность: Office/ODF разбираются локально; распаковываемый XML ограничен 16 МБ.


## D-013 — ДНК 0.4 как доказательный Evidence Engine

- Дата: 2026-10-05.
- Статус: принято.
- Источник: пользователь поручил усилить ДНК «сильнее и умнее» без добавления визуального интерфейса, затем подтвердил «Делай все».
- Решение: существующая вкладка «ДНК» сохраняется без новых визуальных блоков; развитие выполняется в анализаторе, SQLite и API.
- Факт: каждая молекула получает стабильный ID, нормализованное значение, роль, источник, evidence hash и раздельную уверенность извлечения/нормализации/доказательства.
- Эпистемика: доказанный факт и гипотеза являются разными сущностями. Локальный слой 0.4 не создаёт гипотезы автоматически.
- Профили: типы документов имеют собственные обязательные и ожидаемые поля.
- Проверки: арифметика таблиц, внутренние singleton-противоречия, quality gate, risk engine и междокументная сверка.
- Похожие документы: физический SHA-256 не смешивается с семантическим fingerprint; точный дубль, почти-дубль и связанный документ — разные состояния.
- Междокументный слой пересчитывается динамически при чтении, чтобы исправленный конфликт не оставался навсегда.
- Версии: анализы сохраняются в `disk_dna_history`; обратная связь пользователя — в `disk_dna_feedback`.
- Инкрементальность: изменение только метаданных не вызывает повторный разбор содержимого, если SHA-256 и версия анализатора совпадают.
- Память: `memory_ready` является quality gate для будущей памяти; наличие найденного факта само по себе не разрешает сохранять его как проверенное знание.
- Граф: разрешены только доказуемые ребра document→entity/action и связи дубликатов/сходства. Причинность и сложные семантические отношения без ИИ не выдумываются.
- Ограничение: OCR и реальный семантический ИИ остаются отдельными следующими слоями.
