Здесь хранятся устойчивые решения и их причины. Текущее выполнение — в [PROJECT_STATE.md](PROJECT_STATE.md), задачи — в [TASKS.md](TASKS.md).

Статусы: **принято**, **предложено**, **заменено**, **отклонено**. Для каждого нового решения указывай дату, источник и причину. Текст ассистента сам по себе не подтверждает согласие пользователя.

## D-004 — Версия проекта и каждого модуля при любом изменении

- Дата: 2026-10-05.
- Статус: принято.
- Источник: прямое указание пользователя о версии модуля, новой версии при любом изменении и хранении номеров в локальных папках проекта.
- Решение: общая версия в корневом `VERSION`; каждый модуль имеет `VERSION` в своей папке. Любой коммит с изменением повышает проект и затронутые модули.
- Реализация: [VERSIONING.md](VERSIONING.md), [MODULES.json](MODULES.json), [scripts/versioning.py](scripts/versioning.py).
- Начальная фиксация: проект `0.1.1`, служебный модуль `dev-tools 0.1.0`. Это способ внедрения требования; пользователь отдельно не задавал эти числовые значения.
- Причина: GitHub, скачанная папка и следующий чат должны однозначно определять ревизию компонентов.
- Следствие: документация тоже повышает общую версию; новый модуль регистрируется только вместе с реальной папкой.
- GitHub Release не создаётся автоматически; прикладной стек и модель этим решением не выбираются.

| Состав первой рабочей версии | Не определён | Перед началом реализации |

| Память и хранение данных | Не определены | При выборе требований к сохранению |
| Способ установки и запуска | Не определён | При создании рабочего каркаса |
| Перенос оболочки, персонажа или кода из других проектов | Не согласован для этого репозитория | При соответствующей задаче пользователя |

Не подменяй «не определено» старым решением из другого проекта. Если пользователь уже дал ответ в текущей работе, зафиксируй его здесь и не спрашивай повторно.

## Формат нового решения

`D-NNN — название; дата; статус; источник; решение; причина; последствия; какие варианты заменяет.`

При пересмотре сохрани старую запись со статусом «заменено» и ссылкой на новую. Для отклонённого варианта запиши причину, чтобы не предлагать его снова без изменившихся условий.
