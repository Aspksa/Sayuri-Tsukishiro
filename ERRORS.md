# Ошибки и диагностика Саюри Цукисиро

Главные журналы:

- `logs/launcher.log` — переносимый Windows-запуск и предварительная проверка;
- `logs/sayuri.log` — ядро и локальный HTTP-сервер;
- таблица `error_events` в `data/sayuri.db` — настоящие серверные ошибки.

## Коды ошибок

| Код | Значение | Что проверить |
| --- | --- | --- |
| `SAYURI-BOOT-001` | Архитектура Windows не поддерживается | Нужна AMD64/x64 или ARM64 |
| `SAYURI-BOOT-002` | SHA256 Python не совпал | Удалить повреждённый архив в `.runtime/downloads` |
| `SAYURI-BOOT-003` | Runtime распакован неправильно | Удалить `.runtime/python` и запустить снова |
| `SAYURI-BOOT-004` | Python runtime не прошёл проверку | Проверить место, права записи и повторить запуск |
| `SAYURI-BOOT-500` | Ошибка до старта сервера | Смотреть `logs/launcher.log` |
| `SAYURI-PREFLIGHT-001` | Предварительная проверка не пройдена | Проверить VERSION, MODULES.json, базу и права записи |
| `SAYURI-DB-001` | Ошибка SQLite | Проверить `data/`, свободное место и блокировку файла |
| `SAYURI-WEB-002` | Не найден файл веб-интерфейса | Проверить содержимое `web/` |
| `SAYURI-WEB-003` | Сервер не стал готов вовремя | Проверить `logs/sayuri.log` и занятые порты |
| `SAYURI-CORE-500` | Настоящая непредвиденная ошибка ядра | Использовать `request_id` для поиска в журнале |

## WinError 10053

В версии 0.1.2 Windows мог показать `ConnectionAbortedError [WinError 10053]`, когда локальный health-check закрывал соединение раньше окончания записи ответа. Это не означало падение ядра или базы.

С версии 0.1.3:

- health-check дочитывает ответ полностью;
- закрытие браузером/клиентом соединения не записывается как `SAYURI-CORE-500`;
- сервер не отправляет повторный ответ в уже закрытый сокет.

Если такой traceback повторится на 0.1.3 или новее, сохранить `logs/sayuri.log` для отдельного анализа.

## Если сайт не открылся

1. Посмотреть строку «Адрес сайта» в окне запуска.
2. Открыть этот адрес вручную.
3. Проверить `logs/sayuri.log`.
4. Если 8765 занят, Саюри автоматически выберет следующий свободный порт.
5. Если сервер не стартовал, проверить `logs/launcher.log`.

## Безопасность

Сервер слушает только `127.0.0.1`. Внешний сетевой доступ в 0.1.x не включён.
