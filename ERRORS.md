# Ошибки и диагностика Sayuri Tsukishiro

Главные журналы первой рабочей версии:

- `logs/launcher.log` — переносимый Windows-запуск, загрузка runtime и preflight.
- `logs/sayuri.log` — работа ядра и локального HTTP-сервера.
- таблица `error_events` в `data/sayuri.db` — структурированные ошибки приложения.

Пути относительные к корню проекта. При переносе папки на другой диск они не меняются.

## Коды ошибок

| Код | Значение | Что проверить |
| --- | --- | --- |
| `SAYURI-BOOT-001` | Архитектура Windows не поддерживается переносимым launcher | Нужна AMD64/x64 или ARM64 Windows |
| `SAYURI-BOOT-002` | SHA256 скачанного Python не совпал с зафиксированным | Удалить повреждённый файл в `.runtime/downloads`; проверить сеть/антивирус |
| `SAYURI-BOOT-003` | После распаковки runtime отсутствует `python*._pth` | Удалить `.runtime/python` и запустить BAT повторно |
| `SAYURI-BOOT-004` | Переносимый Python не прошёл проверку версии | Удалить `.runtime/python`; проверить свободное место и права на носитель |
| `SAYURI-BOOT-500` | Ошибка старта до запуска веб-сервера | Смотреть `logs/launcher.log` и последнее сообщение консоли |
| `SAYURI-PREFLIGHT-001` | Ядро/SQLite/версии не прошли предварительную проверку | Проверить `VERSION`, `MODULES.json`, права записи и launcher log |
| `SAYURI-DB-001` | SQLite не смог создать/открыть/инициализировать базу | Проверить права на `data/`, свободное место, блокировку файла |
| `SAYURI-WEB-002` | Запрошен отсутствующий статический файл | Проверить папку `web/`; для `/` должен существовать `web/index.html` |
| `SAYURI-WEB-003` | Сервер запущен, но health-check не стал доступен вовремя | Смотреть `logs/sayuri.log`, локальный firewall и занятые порты |
| `SAYURI-CORE-500` | Непредвиденная серверная ошибка | Найти `request_id` в ответе и сопоставить с `logs/sayuri.log` / `error_events` |

## Если сайт не открылся

1. Не закрывать окно `Sayuri Tsukishiro.bat` и посмотреть строку `Local URL`.
2. Открыть этот адрес вручную в браузере.
3. Проверить `logs/sayuri.log`.
4. Если базовый порт `8765` занят, сервер автоматически ищет свободный порт в следующем диапазоне; фактический адрес всегда выводится в консоль и журнал.
5. Если launcher не дошёл до запуска Python, проверить `logs/launcher.log`.

## Безопасность первой версии

Сервер по умолчанию слушает только loopback `127.0.0.1`. Внешний сетевой доступ в `0.1.x` намеренно запрещён конфигурацией. API-ключей и внешнего AI-провайдера в этой версии нет.
