# Ошибки и диагностика Саюри Цукисиро

## Основные журналы

- `logs/launcher.log` — Windows launcher и предварительная проверка.
- `logs/sayuri.log` — ядро и HTTP-сервер.
- `data/sayuri.db` / `error_events` — настоящие серверные ошибки.

## Ошибка кодировки launcher

Симптомы версии 0.1.3:

- `'�ный' is not recognized as an internal or external command`;
- `The string is missing the terminator`;
- `Missing closing '}'`;
- `The Try statement is missing its Catch or Finally block`.

Причина: Windows CMD может начать разбирать BAT до переключения кодовой страницы, а Windows PowerShell 5.1 неоднозначно читает UTF-8 без BOM.

С версии 0.1.4:

- BAT содержит только ASCII;
- PowerShell bootstrap хранится в UTF-8 с BOM;
- CI отдельно проверяет файл через Windows PowerShell.

Если эти ошибки появляются на 0.1.4+, убедиться, что локальные `Sayuri Tsukishiro.bat` и `scripts/bootstrap_windows.ps1` действительно обновлены.

## WinError 10053

В версии 0.1.2 раннее закрытие локального health-check могло давать `ConnectionAbortedError [WinError 10053]`. С 0.1.3 отключение клиента обрабатывается отдельно и не считается `SAYURI-CORE-500`.

## Диск Sayuri

Ошибки валидации Диска возвращаются как `SAYURI-API-400`. Типовые причины:

- имя папки или файла пустое;
- в имени есть `/`, `\\` или управляющие символы;
- файл превышает лимит 1 ГБ;
- передача завершилась раньше заявленного размера;
- создаётся папка с уже существующим именем в той же папке;
- попытка удалить непустую папку.

Отсутствующий файл или папка возвращаются как `SAYURI-WEB-002`/404. Содержимое объектов находится в `data/disk/objects/`; не переименовывать UUID-файлы вручную, иначе метаданные SQLite перестанут соответствовать хранилищу.


## Диск Sayuri 0.2

Типовые ошибки:

- попытка создать/переименовать файл или папку в уже существующее имя;
- попытка переместить папку внутрь самой себя или дочерней папки;
- попытка восстановить объект, если исходное имя уже занято;
- превышение лимита файла 1 ГБ;
- повреждение физического UUID-объекта в `data/disk/objects/`.

Корзина является мягким удалением. Окончательное удаление из корзины удаляет бинарный объект и не восстанавливается средствами Диска. Перед ручной работой с `data/disk/` нужно остановить Саюри.


## ДНК документа

Если ДНК не может быть построена, проверьте:

- физический объект существует в `data/disk/objects/`;
- SHA-256 оригинала совпадает с метаданными;
- Office/ODF-файл является корректным ZIP-контейнером;
- распаковываемый XML не превышает безопасный лимит 16 МБ;
- документ содержит локально извлекаемый текст.

Для PDF-сканов и изображений отсутствие текста является ожидаемым состоянием до подключения OCR и не должно интерпретироваться как успешный полный анализ.


## ДНК 0.4

Дополнительные диагностические состояния:

- `integrity_failed` — физический SHA-256 не совпадает;
- `critical_risk` — сработало критическое правило, например арифметическое расхождение;
- `contradiction_requires_review` — найдено внутреннее ключевое противоречие;
- `cross_document_contradiction` — документ расходится с документом того же типа/номера;
- `no_accepted_facts` — нет фактов, прошедших quality gate.

Эти состояния не удаляют документ. Они запрещают считать ДНК готовой к автоматическому переносу в будущую проверенную память.

Если меняется только имя/папка файла, но SHA-256 прежний, повторный тяжёлый анализ содержимого не требуется. Если меняется SHA-256 или версия анализатора, создаётся новая версия ДНК.


## ДНК 0.5

Новые диагностические признаки:

- `prompt_injection_review` — внутри документа обнаружена фраза, похожая на инструкцию модели; она остаётся обычными данными и блокирует автоматическое продвижение в память до проверки;
- `temporal_contradiction` — найдено доказуемое временное противоречие;
- `disk_dna_ledger.valid=false` — нарушена hash-chain истории ДНК; требуется проверка базы/ручного вмешательства;
- `dependencies.unresolved_count > 0` — документ ссылается на другой документ, которого ДНК пока не смогла сопоставить;
- `anomalies.count > 0` — документ заметно отличается от медианы документов того же типа; это сигнал для проверки, а не доказанная ошибка.

Correction Memory не применяет правило, пока его не подтвердили одинаковым исправлением минимум в трёх разных документах.
