## Reasoning Logic 2.0

Sayuri использует локальную deterministic state machine поверх существующих Planner/Verifier:

`UNDERSTAND → RETRIEVE → FRAME → PLAN → CHECK → ACT → VERIFY → REFLECT → CONTINUE`.

При неопределённости и сбоях используются отдельные ветви `GATHER_EVIDENCE`, `REPLAN` и `READY_FOR_CONFIRMATION`.

- blockers и high uncertainty имеют приоритет над уверенным текстом модели;
- Planner 2.0 возвращает проверяемые assumptions/hypotheses/options/counterfactual checks без chain-of-thought;
- Result Verifier проверяет goal/constraints/evidence и может отправить маршрут в REPLAN;
- completion readiness не превращается в автоматический `done`;
- пользователь видит компактный Decision Trace, а не скрытые рассуждения;
- простые запросы остаются быстрыми и не вызывают лишние Planner/Verifier calls;
- единственная внешняя LLM — `deepseek-ai/DeepSeek-V4-Flash`.

Подробный контракт: [REASONING_LOGIC.md](REASONING_LOGIC.md).

## Cognitive Project Brain 1.0

`0.2.0` переводит Sayuri от «умной памяти с Planner» к проектному когнитивному ядру, рассчитанному на большое число модулей и отдельных проектов.

Новая иерархия:

`Portfolio → Project → Module → Goal/Task → Dependency Graph → Completion Criteria → Scheduler → Checkpoint/Evidence → Evaluation`

Основные правила:

- любой модуль из `MODULES.json` автоматически попадает в Cognitive Brain;
- будущий модуль может передать `project_key` / `module_key` в task context и получить отдельный scope без изменения кода мозга;
- task graph поддерживает `requires`, `blocks`, `unlocks`, `follows`;
- scheduler выбирает только разблокированную задачу;
- completion criteria оцениваются детерминированно и не закрывают задачу автоматически;
- failure создаёт replan proposal и uncertainty вместо самовольного переписывания плана;
- подтверждённые Action Broker исходы обучают Strategy Memory статистически;
- metacognition явно различает известное, неопределённое, заблокированное и требующее replanning;
- состояние долгих проектов сохраняется между перезапусками;
- модель видит этот слой только как read-only контекст.

Для диагностики доступен локальный read-only endpoint `GET /api/sayuri/cognition?q=...`.

## Task Lifecycle & Checkpoints

С `0.1.56` Goal Continuity получила устойчивый жизненный цикл многошаговых задач:

- подтверждённое действие Action Broker может создать checkpoint связанной задачи;
- checkpoint создаётся только после фактического `completed`, а не по заявлению модели;
- связь action → task устанавливается локально и детерминированно по совпадению текущей команды с активной задачей;
- результат получает SHA-256 evidence digest, sequence number и состояние задачи до/после;

- после перезапуска Sayuri последняя контрольная точка и следующий шаг восстанавливаются из `sayuri-memory.db`;

Это сохраняет главный security invariant: **LLM планирует и объясняет, локальный deterministic lifecycle фиксирует подтверждённые факты, а любые реальные mutations по-прежнему проходят через Action Broker**.

## Безопасные действия Sayuri

Sayuri может готовить изменяющие действия внутри проекта, но не выполняет их без подтверждения пользователя.

Примеры команд в чате:

- `создай папку Договоры`;
- `добавь этот документ в избранное`;
- `удали этот документ`;
- `перемести этот документ в папку Архив`;
- `запомни как решение проекта: ...`.

Перед изменением появляется карточка с точным действием, уровнем риска и кнопками «Подтвердить» / «Отменить». Повторный confirm не выполняет действие второй раз.

## Reasoning Planner + Result Verifier

Начиная с `0.1.47`, сложные запросы Sayuri проходят дополнительный контролируемый reasoning pipeline:

```text
complexity gate
→ structured task-plan
→ основной ответ
→ Result Verifier
→ при необходимости revised answer
```

Planner хранит только цель, шаги, ограничения, нужные доказательства и критерии готовности. Внутренняя chain-of-thought не сохраняется и не показывается.

Простые запросы не получают лишние вызовы модели. Для сложных задач Planner, основной ответ и Verifier используют одну и ту же внешнюю модель `deepseek-ai/DeepSeek-V4-Flash` через Cloud.ru. Вторая LLM не добавлена.

Verifier отдельно проверяет покрытие исходной задачи, ограничения и доступные evidence blocks. Если нужно исправление, он возвращает полную исправленную версию ответа в том же verification-вызове.

## Фоновая Evidence Automation

Начиная с `0.1.49`, технические инструменты не вынесены в отдельный пользовательский интерфейс. Для сложной задачи Sayuri сама может выполнить разрешённые read-only проверки в фоне и передать их фактические результаты Result Verifier.

DeepSeek может предложить structured intent, но право исполнения остаётся у локальной deterministic policy. Дополнительно policy умеет сама подобрать безопасную проверку по `goal/evidence_needed`: память, состояние системы, integrity, текущий документ или статистика опыта.

Любое изменение состояния по-прежнему помечается `requires_action_broker` и не выполняется без существующего подтверждаемого Action Broker. Неизвестные действия отклоняются.

Execution receipts с SHA-256 и evidence refs сохраняются локально для проверки и диагностики, но обычный чат их не показывает. В reasoning summary появляется только компактная отметка `автопроверка N`, если такие проверки действительно выполнялись. Меню проекта не менялось.

## Memory 4.0

### Memory 4.1 Quality Gate

В `0.1.46` память получила дополнительный quality-layer. Оценка «Полезно / Не помогло» теперь обучает только retrieval utility и не меняет доверие к источнику. High-risk instruction-like память («игнорируй инструкции», попытки раскрыть system prompt и аналогичные конструкции) остаётся локальной и не проходит в Cloud.ru ни напрямую, ни через соседние memory layers.

Recall диверсифицируется, чтобы почти одинаковые записи не занимали весь контекст. Для Cloud-context действуют отдельные бюджеты; длинные записи сокращаются только в передаваемом excerpt. Важные volatile facts с низкой freshness автоматически появляются в Question Memory как запрос на перепроверку.


Начиная с `0.1.44`, память Sayuri получила отдельный policy/orchestration слой поверх Memory 3.0.

Memory 4.0 добавляет:

- Goal Memory и Task Memory для долгосрочных целей, незавершённых задач, следующего шага и блокеров;
- Source Trust и Freshness для оценки происхождения и актуальности памяти;
- Utility Learning по обратной связи на ответы, где память действительно использовалась;
- Hot / Warm / Cold tiers без автоматического удаления;
- Decision Memory с причиной/альтернативами только когда они явно известны;
- Failure & Causal Memory для повторяемых ошибок, наблюдений и подтверждённых исправлений;
- Question/Uncertainty Memory, чтобы сомнение не превращалось в факт;
- Entity Profiles и историю изменения preferences;
- Explainable Recall — «почему Sayuri вспомнила именно это»;
- Memory Audit;
- integrity check;
- локальные SQLite snapshots с SHA-256.

Секретная и чувствительная память помечается `LOCAL ONLY` и исключается из контекста, отправляемого в Cloud.ru. Начиная с `0.1.45`, этот privacy-инвариант действует сквозным фильтром и на производные контуры Memory 3.0, Experience, Goals, Tasks, Failures и Questions.

Локальный поиск в Личном кабинете показывает Explainable Recall, но не считается обучающим сигналом и не увеличивает utility/use counters. AI recall фиксируется как реально использованный только после успешного ответа Cloud.ru; timeout/provider error не обучает память. Успешный запуск после ошибки сохраняется как слабое наблюдение `followed_by_success`; Failure Memory считается исправленной только после явного подтверждения пользователя.

Восстановление snapshot требует точного подтверждения `RESTORE MEMORY` и предварительно создаёт страховочную копию текущей памяти.

## Memory 3.0

Sayuri использует несколько специализированных контуров памяти:

- **Working Memory** — текущая задача и интерфейсный контекст с TTL;
- **Episodic Memory** — значимые события и исходы;
- **Knowledge Memory** — подтверждённые устойчивые знания с источниками;
- **Temporal Memory** — история изменений и актуальности;
- **Knowledge Graph** — связи между пользователем, проектом, документами, решениями, знаниями и сущностями.

Memory Consolidation объединяет похожие записи в устойчивое знание без удаления источников. Forgetting Engine не стирает старую память — он снижает её retrieval-вес. Противоречия разрешаются пользователем в Личном кабинете.

## Semantic Memory

Sayuri ищет долговременную память не только по точным словам, но и по близким формулировкам. Текущий локальный engine — `hybrid-semantic-v1`.

Он использует ключевые слова, лёгкую нормализацию словоформ, локальные смысловые понятия и похожесть формулировок. Это не neural embeddings и не отдельная внешняя модель.

Личная и проектная память по-прежнему выдаются отдельно.

## Experience Learning

Sayuri ведёт отдельную локальную память опыта:

- успешные/неуспешные подтверждённые действия;
- принятые/отклонённые кандидаты памяти;
- оценки ответов «Полезно / Не помогло».

Experience Learning помогает не повторять неудачные подходы и немного калибрует уверенность Memory Intelligence. Он не меняет разрешения инструментов и не отменяет обязательные подтверждения.

## Semantic Memory и Experience Learning

Начиная с `0.1.42`, Sayuri ищет память через локальный `hybrid-semantic-v1`: учитываются не только точные слова, но и формы слов, известные смысловые понятия и похожие формулировки. Это прозрачный локальный механизм, а не отдельная neural embedding-модель.

Отдельно ведётся память опыта. Sayuri фиксирует успешность разрешённых инструментов, принятые/отклонённые кандидаты памяти и явную оценку ответов «Полезно / Не помогло». Положительный и отрицательный опыт может использоваться как справочный контекст следующей похожей задачи.

Experience Learning не расширяет права инструментов и не отключает подтверждения. Единственная внешняя LLM остаётся `deepseek-ai/DeepSeek-V4-Flash` через Cloud.ru.

## Memory Intelligence 2.0

Sayuri автоматически замечает потенциально важные предпочтения, решения, правила, задачи и технические факты, но не сохраняет весь разговор.

Найденное сначала становится кандидатом памяти. В Личном кабинете можно проверить confidence, источник и контекст, затем сохранить или отклонить. Дубли отбрасываются, возможные противоречия выделяются отдельно.

Автосохранение по умолчанию выключено. При ручном включении оно ограничено высокоуверенными проектными фактами.

## Память Sayuri

Sayuri имеет локальную долговременную память с двумя строго разделёнными областями:

- личная (`personal`);
- проектная (`project`).

Управление находится в Личном кабинете. Обычные сообщения автоматически не сохраняются. Для быстрого явного сохранения используются фразы «запомни лично: …» и «запомни в проект: …».

## Аватары Sayuri

В Личном кабинете можно назначить отдельные локальные изображения для плавающего аватара, чата, профиля и большого портрета. Поддерживаются PNG/JPEG/WebP; файлы остаются в `data/` и не отправляются в GitHub.

## Evolution Core 0.6

Без новых элементов меню ДНК умеет:
- проводить самопроверку результата;
- блокировать регрессию нового анализа;
- формировать адаптивные ожидания по накопленному корпусу;
- различать candidate/shadow/active правила;
- хранить гипотезы отдельно от фактов;
- выбирать самые полезные факты для будущей проверки;
- объединять одну реальную сущность между разными документами;
- строить план переанализа устаревших ДНК;
- не плодить версии при нескольких одинаковых нажатиях «Переизучить» подряд.

Эволюция основана только на проверяемых данных и обратной связи пользователя.

## Spatial DNA 0.7

Для PDF:
- native text извлекается вместе с геометрией;
- сканированные/малотекстовые страницы направляются в локальный Tesseract OCR;
- факты Evidence Engine могут получить точную страницу и bbox;
- OCR сохраняет confidence;
- spatial snapshot имеет собственный fingerprint и кэш.

Для изображений OCR выполняется локально через Pillow + Tesseract при готовом runtime.

Без vision/semantic AI таблица, подпись и печать называются только кандидатами. Это защищает ДНК от ложной уверенности.
